Product Backlog — User Stories (Draft v0.1)

Decks

    US-01 (Sprint 1)
    As a user, I want to create a new deck so that I can organize flashcards by topic.

    US-02 (Sprint 1)
    As a user, I want to view a list of my decks so that I can choose what to study.

    US-03 (Later)
    As a user, I want to rename a deck so that I can keep my deck names accurate.

    US-04 (Later)
    As a user, I want to delete a deck so that I can remove material I no longer need.

Cards

    US-05 (Sprint 1)
    As a user, I want to add a flashcard to a deck so that I can store study material.

    US-06 (Later)
    As a user, I want to edit an existing card so that I can correct mistakes or improve wording.

    US-07 (Later)
    As a user, I want to delete a card so that I can remove irrelevant or incorrect content.

    US-08 (Later)
    As a user, I want to view all cards in a deck so that I can review what’s inside before studying.

Study Mode

    US-09 (Later / could be Sprint 2)
    As a user, I want to study a deck by viewing one card at a time so that I can focus on active recall.

    US-10 (Later / could be Sprint 2)
    As a user, I want to flip a card between question and answer so that I can check my response.

Scheduling and Tracking (Algorithms Core)

    US-11 (Core planned for algorithms sprints)
    As a user, I want the system to prioritize cards that are “due” so that I spend time on the most important cards first.
    (Implementation target: min-heap / priority queue)

    US-12 (Core planned for algorithms sprints)
    As a user, I want card lookups and updates to be fast so that studying stays responsive as decks grow.
    (Implementation target: hash-based structure used for lookup/support operations)
